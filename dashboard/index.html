CVE lookup

Two questions, one box. Give it an advisory identifier and it reports which repositories are exposed. Give it a package name and it reports where that package is used, at which versions, and whether any copy is vulnerable — which is the answer when someone asks “do we use this anywhere?”

Accepts an advisory identifier (CVE, GHSA, PYSEC); a Package URL; a package name; or a version range exactly as an advisory states it — lodash < 4.17.21, log4j-core < 2.15.0, minimist <= 1.2.5. Every component in the estate is evaluated against the bound, so you are not comparing version numbers by eye.

Prioritisation evidence

Does ranking by business impact actually beat ranking by technical severity? Both orderings contain the same findings, so the only way to tell is to have a person judge what matters, then measure which ordering agrees more closely.

Step 1  ·  Grade the sample

Judge each finding on what it would cost the business if left unfixed — not on how severe the vulnerability is. Severity is already accounted for elsewhere. The scores are hidden so your judgement stays independent of the model.

3 fix first — revenue-critical or regulated 2 fix soon — important, not critical 1 scheduled — limited consequence 0 ignore — no meaningful consequence
